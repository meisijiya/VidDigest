请对以下视频字幕内容做一次拆解，一次给出三样东西：总结、思维导图、标签。使用$lang_hint输出。

【第一部分：总结正文】
一、格式（照做即可）
1. 必须输出标准 Markdown，并使用多级标题构建清晰的层级结构：
   - `# 视频主题`：一级标题，全文有且仅有一个；
   - `## 章节`：二级标题。教程类内容优先用这几类章节：
     `## 准备`（要准备什么）、`## 步骤`（怎么做）、`## 注意事项`（哪些坑）、
     `## 常见问题`（字幕里真的提到的疑问）；按视频实际内容取舍，
     但「步骤」这一节必须有；
   - `### 小节`：三级标题用于章节内部的细分要点。
2. 严禁用 `**加粗**` 代替标题，所有章节标题都必须以 # 号开头独占一行。
3. 「步骤」这一节用**有序列表**（`1. `）编号，每一步独占一行；其余章节用
   无序列表（`- `），子要点通过缩进（`  - `）形成层级。
4. 只输出 Markdown 正文，不要输出代码块围栏，也不要任何解释性文字。

二、内容
5. 每一步都要**可执行**：写清做什么、用什么、按什么顺序、做到什么程度。
   不接受「设置一下」「配置好」这种读者仍然不知道怎么动手的句子。
   - 反例：`3. 配置环境变量`（没说要配哪个、值是什么）
   - 正例：`3. 在项目根目录建 .env，写入 API_KEY=你的密钥，这一步不要提交到仓库`
6. **覆盖优先**：字幕里实际演示过的步骤都要出现，不要因为「看起来简单」
   就略过；视频没讲到的步骤不要自己补。
7. **篇幅**：正文不少于 800 字（不含标题行）。宁可把一个步骤的前提与
   失败表现讲透，也不要只留一串动作名词；同时不要用重复的话凑字数。
8. 字幕里没有的信息不要编造。听不清、字幕本身就没展开的部分，直接略过。

【第二部分：思维导图】
（下面的长度与节点数限制**只适用于思维导图**，不要套用到第一部分的总结正文。
导图刻意精简、总结正文刻意详实，这是两件不同的事。）
只输出 Markdown 标题层级结构，禁止代码块围栏、禁止任何说明、问候或总结性文字：
- `# 视频主题`：一级标题，有且仅有一个，作为导图中心主题；
- `## 主要章节`：二级标题，作为一级分支（一般 3-6 个）；
- `### 次级要点`：三级标题，作为二级分支；
- `- 细节要点`：无序列表，作为叶子节点（可选）。
每个节点文字尽量不超过 15 个字，全图节点总数控制在 30 个以内。
导图的结构上限（超出的部分会被截断，所以要自己控制）：
- 层级最多 3 级：`#` → `##` → `###`，不要出现 `####`；
- 同一个父节点下最多 7 个子节点；
- 至少 2 个二级分支，每个分支下再挂 1-2 个三级要点——只有一层等于没给。

【第三部分：标签】
（同样只约束标签本身，不影响前两部分。）

判断依据是这个视频**在讲什么题材**，不是「它对某个行业有没有用」：
一段讲劳动仲裁的普法视频属于职场题材，哪怕观众大多是做技术的。

从下列固定词表中选出最多 3 个最贴切的标签，必须用词表里的中文原词，
不要自创近义词（例如不要写「AI 编程」「编程教学」）：
$vocabulary

「其他」只在题材真的不属于上面任何一类时才用。拿不准就选最接近的那一类，
不要直接落到「其他」——它是最后的兜底，不是「不确定」的同义词。

判断示例，每行左边是题材、右边是应选的标签，标签都取自上面这张表：
  用 Python 写爬虫踩坑              → 编程
  横向对比几个大模型的编程能力        → 人工智能、编程
  实习生被违法解除该怎么办            → 职场维权
  某地土地财政与房价走势              → 财经投资、时事评论
  盘点国庆游戏打折到底值不值          → 游戏、电商优惠
  三款扫地机器人横测                 → 数码测评
  一个人把游戏发行跑通                → 游戏、创业
  讲金庸武侠小说的写作背景            → 读书、影视

【输出格式 —— 必须严格遵守】
第一部分正文之后，另起一行输出哨兵行（一个字都不能改，也不要加代码块围栏）：
$sentinel
紧接着输出一行 JSON，形如：
{"mindmap": "# 视频主题\n## 主要结论\n### 结论要点\n## 关键数据\n### 对比数据", "tags": ["编程", "人工智能"]}

完整示例（步骤是编号的，每一步都写清了做什么、怎么做到位）：
# 用 Git 推第一个 PR 的完整步骤
## 准备
- 装好 Git，并一次性配好用户名与邮箱，之后所有仓库都生效
- 在远程平台上先建一个空仓库，本地只保留提交历史
## 步骤
1. 在项目目录里跑 `git init` 建立本地仓库
2. 跑 `git add .` 把改动放进暂存区，再用 `git commit -m "说明这次改了什么"` 提交
3. 跑 `git remote add origin <远程仓库地址>` 绑定远程
4. 跑 `git push -u origin main` 把本地分支推上去并建立跟踪关系
5. 在平台上开一个合并请求，把这条分支并回主分支
## 注意事项
- 提交前先跑 `git status` 确认没有把密钥之类的文件带进去
- 不要在主分支上直接提交，先切一条自己的分支再动手
$sentinel
