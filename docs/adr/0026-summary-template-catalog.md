# ADR 0026：总结模板清单只有一份，模板 id 显式穿过接缝

## 决定

### 1. 清单只有一份真值

模板清单的唯一真值是 `backend/prompts/templates.json`：一个 `default` 字段加一组
`{id, name, description, file}`。提示词文件本身**不**放展示用元数据——每份
`backend/prompts/summarize_*.md` 各自写一份「这个模板叫什么」，那就有四份真值，
改一个模板名要改四个文件，漏一个就出现「下拉框里的名字和实际用的提示词对不上」。

### 2. 模板 id 与文件名解耦

- `id`（`full` / `brief` / `tutorial` / `analysis`）是**接口与界面**用的稳定标识。
- `file`（`summarize_full` / `summarize_brief` / …）是提示词文件的 stem。

清单负责 id → file 的映射，`backend/prompt_template.py` 是唯一做映射的地方。
界面与请求体里流转的永远是 id，不出现文件名。

### 3. 清单端点只读、匿名可读

`GET /api/summary-templates` 返回 `{default, templates: [{id, name, description}]}`。
**不返回 file**：文件名是内部实现，前端拿它没有正当用途，一旦前端开始按文件名
判断「这是哪个模板」，就等于把清单又复制了一份。

### 4. 请求体里的 `summary_template`：空即默认，未知即拒绝

- 不传（或传空串）= 服务端用默认模板 = 现在的行为。
- 传了未知的 id = **422**，不静默回退到默认。

静默回退是最坏的失败模式：用户选了「精简摘要」，拿回来的是详尽总结，**全程
不报错**。要让用户看见错误，就得让请求失败。

### 5. 模板参数显式穿过接缝

`VideoSummarizer.summarize_full_stream(text, language, template)` 的第三参是模板 id，
`None` 表示默认模板。模板 id 一路显式传到渲染提示词的那一步
（`backend/summarizer.py` 的 `_build_full_prompt`），不藏在全局变量、ContextVar
或环境变量里。

SSE 事件集**不变**：仍然只有 ownership / subtitle / summary / mindmap / tags /
quota / error / done。模板不进事件流——它不是逐帧内容，是这次解析的输入。

### 6. 落库 `videos.template`

社区视频表加一列 `template`，**解析完成时才写**（占位行是 NULL）。老库走一条
补列 + 回填的迁移（`backend/database.py` 的 `_migrate_videos_template_column`）：
补列之后把空值回填成默认模板，于是老行读出来也是合法的模板 id。

读出口是 `get_video_by_url`（`SELECT *`，新增列自动出现），社区复用同一条总结时
才知道它当初是用哪个模板做的。

### 7. 前端：下拉框的选项从端点读

`frontend/src/components/VideoSummary.vue` 的下拉框选项来自
`GET /api/summary-templates`，**前端不硬编码模板名单**。清单取不到时降级：
不渲染下拉框、留一句说明、解析照常进行（服务端会用它的默认模板）。

### 8. Markdown 排版只用 CSS

`.summary-content` 的表格、引用块、代码块、分隔线等排版规则写在
`frontend/src/style.css` 里，只用已有的 CSS 变量，不引新的 UI 库、不引新的构建依赖。

## 为什么

- **清单只能有一份**。两份清单的症状不是报错，是「界面上的选项和后端认的模板
  对不上」——用户点一个就 422，而 422 的提示里没有任何线索指向「你的界面过期了」。
- **id 与文件名解耦**是为了让文件名可以随便改（`summarize_full.md` →
  `summarize_detailed.md`）而不动接口。接口里出现文件名，等于把磁盘布局写进契约。
- **未知 id 报 422 而不是回退**：回退会让「模板选择」这个功能在最需要它的时刻
  （用户想换个模板）静默失效，而失效点在服务端、报错点在界面，中间隔着一层网络。
- **显式第三参，而不是隐式通道**：隐式通道（全局变量 / ContextVar）在并发解析时
  会串味——A 用户的请求可能渲染成 B 用户选的模板，而且没有任何报错。显式参数把
  这个风险变成不可能。
- **接缝签名变了**（多了第三参）是有代价的：全仓 16 处测试桩要跟着改。
  但改桩签名是接缝契约的机械适配，不动任何断言；反过来，把模板塞进隐式通道
  才能做到「一行桩都不用改」，代价是上面那条串味风险。
- **`videos.template` 要落库**：社区里同一条视频可能被不同的人用不同模板解析过，
  复用与重生成时需要知道上一份总结是怎么来的。
- **降级而不是拦截清单请求**：清单取不到时，用户仍然想要总结。拦住解析是把一个
  辅助信息的故障升级成主流程的故障。
- **排版只用 CSS**：项目里已经有 Tailwind typography 插件与一整套 CSS 变量令牌，
  再引一个 Markdown 渲染库会引入第二套排版规则，主题跟随（暗色默认 + 亮色覆盖）
  也就断了。

## 代价

- **接缝签名变了**：`summarize_full_stream` 多一个可选第三参，16 处测试桩的签名
  要同步扩宽。桩只计调用次数、不记参数，所以扩宽不改变任何既有断言。
- **`backend/prompts/` 目录多了一个 JSON**：提示词文件不再是那个目录里唯一的
  东西。它是清单文件，不是配置片段——真值只有这一份，改它就会改全链路的可见行为。
- **未知 id 直接 422**：调用方（前端、脚本）传错就整个请求失败。对内部调用点是
  好事，对外部使用者是新增的失败模式。
- **`videos` 表多一列**：老库必须跑一次补列迁移；不迁移就读不到该列。
- **前端多一次请求**：挂载组件时多打一个 GET。它不消耗额度、可以匿名读，代价可忽略。
- **四份模板各带完整 few-shot**：文件比「一份模板 + 参数」大得多。换来的是每份
  模板的形状由自己的样例教——散文规则管不住形状，样例可以。
