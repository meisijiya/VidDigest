# 前端路由：引入 vue-router，取代手写的轻路由

> **部分已被 ADR 0025 修正（2026-10-25）**：第五条真实路径 `/admin/invite-codes`
> （邀请码管理页）已加入，本文写的「四条真实路径」不再完整。
> 本文件保留原样是为了留住当时的论证——ADR 0025 里写了它为什么不再成立。

**决定**：前端引入 `vue-router`，用四条真实路径（`/`、`/history`、`/community`、
`/admin`）替换 `frontend/src/App.vue` 里手写的 `PATHS` / `pageFromPath` /
`pushPage` / `syncPageFromUrl`。

本 ADR 取代 ADR 0017（"前端路由：轻量自实现，不引 vue-router"）。0017 当时的
事实——"三个页签共享 `/`"——已经变了：现在三个页签各有自己的路径。

## 为什么

**为什么反转**：0017 成立的前提是"URL 变化对用户没有信息量"，而那个前提已经不成立了。

- 手写路由的能力边界已经被越到。它没有嵌套路由、没有守卫、没有异步懒加载、
  没有导航钩子；再往后长出详情页、或者要给 `/admin` 加一个"未登录先跳登录页"
  的前置，只能继续手写。手写的部分越多，扔掉它越贵。
- 四个视图已经各自有了明确语义（主页 / 历史 / 社区 / 管理后台），路径是产品语义
  的一部分，不只是页签索引。URL 可分享、可收藏、可被直接打开，这三件事手写
  路由本来就支持，但**没有历史栈、没有后退**——而后退是浏览器默认行为里最被
  依赖的一个。
- 本项目要同时面对软件开发与全栈两类岗位。路由是前端工程化里最容易被追问的
  一环（"路由守卫怎么做的？""懒加载怎么切的？"）。手写实现能答，但答的是
  "我自己写了个东西"；用框架并把取舍讲清楚，答的是"我知道边界在哪"。两者
  在面试里不是同一个量级。

**为什么现在反转成本最低**：只有 4 个视图、53 个组件、没有历史路由别名负担、
没有外部链接依赖旧路径格式。现在换，比长出详情页之后再换便宜。

## 代价

- 多一个运行时依赖（`vue-router`），换来的能力前面已经列了。
- `/admin` 必须是**真实路径**，所以部署时需要服务端把未匹配的路径回落
  `index.html`（Nginx `try_files`）。这是手写路由时代不存在的部署约束。
- 引入守卫就引入时序问题：鉴权还没完成时不能决定放不放行。守卫必须能
  "等待异步结果"，而不是"同步看一眼再跳"。

## 推翻条件

如果将来要支持多级嵌套路由与路由级代码分割，`vue-router` 是前提而不是可选项。
反过来，如果这套应用退回到"只有一个视图 + 一个管理后台"的规模，本 ADR
应当被再次审视。

## 后果

- `frontend/package.json` 会出现 `vue-router`；它**不是**"顺手加的依赖"，
  是本 ADR 的直接后果。
- `frontend/src/App.vue` 里那段手写路由代码整体删除，`App.vue` 顶部的注释
  从 ADR 0017 改指本 ADR。
- 页面间跳转不再直接改 `currentPage`，而走路由；`currentPage` 变成路由的
  派生状态（由 `useRoute()` 读），不是独立的事实来源。
