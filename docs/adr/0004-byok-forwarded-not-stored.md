# 用户自带密钥时由服务端转发，但绝不落盘

用户可填入自己的模型服务凭据。凭据只存在于浏览器本地，服务端不建表、不写日志、不持久化，
仅在单次请求的内存中转发给模型服务商。用户自带密钥的调用不消耗账号额度。

## Consequences

**这条决定了实现的形态**：请求仍然发往服务端，因此可以沿用现有的流式响应，
前端交互与平台模型路径完全一致，无需为自带密钥另写一套流式解析。

## Considered Options

- 浏览器直连模型服务商：凭据完全不经过服务端，隐私姿态最强。
  但要额外实现一套基于 fetch 与可读流的流式解析，各家 OpenAI 兼容接口的流式格式有差异，且跨域受限。
  相比之下「服务端转发但不落盘」已经满足「不存储凭据」这一实质承诺。

## 已验证：HTTP 客户端的调试日志不打印认证头

实现前实测（2026-10-01，httpx 0.28.1 / openai）：把 `httpx`、`httpcore`、
`openai` 全部日志器设为 DEBUG，发起一个真实请求，确认服务端确实收到了认证头。
调试输出中**不含凭据字面量、不含 Authorization 字段名、不含 Bearer**——
httpcore 只记录 `send_request_headers.started request=<Request [b'POST']>` 这类方法级信息。

因此「转发」不会通过第三方库的调试日志泄漏凭据。
剩余风险集中在**本项目自己的代码**：异常分支若把异常对象直接塞进响应就会泄漏，
所以必须对凭据做结构性遮蔽，而不是依赖第三方库。
