# ADR 0029：思维导图结构只有一份真源，存量迁移连超上限的行一起收拾

本 ADR 修正 ADR 0027 的两处表述，其余决定不变：

- 「前端仍有一份同款旧清洗逻辑」——**已删除**。导图结构由 `backend/mindmap.py`
  单独说了算，前端不再洗一遍。
- 「存量重建只覆盖退化（层级 < 2）的行」——**扩到两类**：退化行按同行总结正文
  重建，层级够但超上限的行按当前规则截回上限之内。

## 决定

**导图结构只有一份真源**：`backend/mindmap.py`。前端拿到的 markdown **原样**交给
markmap 渲染，不再自己洗一遍。

- 导图内容为空 → 走「暂无思维导图」空态（**空态不是清洗规则**）。
- 导图渲染不出来 → 走模板里的失败兜底，把原始 markdown 显示出来。
- 前端**不做**任何结构改写：不提升根标题、不下移后代、不补根标题、不把纯文本
  行转成列表。

**存量迁移收拾两类行**（`backend/database.py` 的 `_migrate_mindmap_levels`，
`init_db()` 时跑）：

- **退化行**（层级 < 2）：从同一行的总结正文重建导图。没有总结正文的行
  **原样保留**（宁可留一根光杆，也不编一棵导图出来）。
- **层级够但超上限的行**（每支 > 7 或全图 > 30）：按当前规则截回上限之内。
  截断只丢超出的节点，不拿总结正文替换。
- 已经在上限之内、层级也够的行：**一个字符都不动**。

「超上限」的判定不抄第二份规则：`backend/mindmap.py` 的 `exceeds_limits(md)`
用同一棵解析树问一句「按规则洗一遍会不会少节点」——会少就是超限。

## 为什么

- **两份规则迟早分叉，而分叉的那一份没人测**。前端那份复制品（把首个 `##`
  提升成 `# ` 却**不**把后代同步下移）在后端现在的产出上是幂等的，但它对
  **存量库里的 `##` 根老行**不幂等：提升之后，原来的 `###` 变成「比根深两级」
  的孤儿标题，markmap 建树时会把父节点的孩子整个清掉——**第三级节点凭空
  消失**，用户看到的是「导图少了一层」，而后端那份数据是合规的。
- **源码正则断言 ≠ 真挂载**。思维导图此前没有一条「点了真渲染出来」的用例；
  判据必须落在渲染结果上（第三级节点在不在 DOM 里），而不是源码长什么样。
- **迁移只覆盖退化行，规则对存量库就是空话**。层级够但超上限的老行不会被
  收拾，前端照样渲染一棵几十个节点的导图，ADR 0027 的三个上限对存量库形同
  虚设。
- **空态不是清洗规则**。没有内容时显示「暂无思维导图」是界面状态；把它写进
  清洗函数，就等于承认「前端还得自己决定结构」。

## 代价

- **截断超上限的存量行会丢内容**。与 ADR 0027 的截断代价同源：被丢掉的
  分支整支消失，用户看到的内容比库里存的少。
- **前端不再兜底**。后端交来的导图若不合规，前端不会替它修；渲染失败有失败
  兜底，但不会给出合规的导图。这是刻意的：兜底的那一份永远没人测。
- **迁移时每行要再解析一遍**。`exceeds_limits` 与 `clean_mindmap_markdown`
  走的是同一棵树的两次渲染；老库大时 `init_db()` 慢一点。换来的是「判定超限」
  与「执行截断」用的是同一套规则，不会各写一份。

## 推翻条件

- 换掉 markmap 或改前端渲染契约（层级语义、列表叶子的处理会一起变）。
- 前端需要独立于后端地兜底（例如导图数据来自后端之外的数据源）。
- 改这三个上限的数值或含义（`backend/mindmap.py` 的常量与
  `backend/tests/test_mindmap_levels.py` 的字面量断言要一起改）。

## 后果

- `frontend/src/components/VideoSummary.vue` 里的 `sanitizeMindmap` 已删除，
  渲染时 `transformer.transform(mindmapMd.value)` 原样交给 markmap。
- 读出口有覆盖：`frontend/tests/video-summary.mount.spec.mjs` 的
  「思维导图渲染」一节是真挂载用例（第三级节点渲染后仍在、后端形状的导图作
  反向对照、没有导图时是空态），跑 vitest。
- 写迁移有覆盖：`backend/tests/test_mindmap_migration.py` 从**真老库 DDL**
  起步，钉住退化行被重建、超上限行被截回上限、没有正文的行原样保留、迁移
  **幂等**（连跑多次结果相同）。
- 结构性约束由变异确认：`backend/tests/mutation_prompt.py` 的 M6（退化重建
  空转）与 M7（迁移不再收拾超上限的行），`frontend/tests/mutation-ui-fixes.mjs`
  的 M32（前端把那份复制品装回去）。KILLED 必须伴随 `AssertionError`。
- 运维口径（导图规则、存量迁移收拾哪两类行）写在 `docs/OPERATIONS.md`。
