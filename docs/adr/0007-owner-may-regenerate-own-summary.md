# 首次解析者本人可以覆盖自己那一份总结，后来者不能

ADR 0006 规定同一视频只解析一次、后来者复用首份。0006 否决「后来者覆盖首份」的理由是
**任何人可改写他人的内容**。这个理由成立，但它把两类改写混成了一类：

- **A 类：改写别人写的内容**——仍然必须禁止。
- **B 类：改写自己写的内容**——首份总结可能是在旧提示词、旧模型或错的语言设置下产出的，
  作者本人没有理由只能看着它。

因此本 ADR 只在 B 类上开口子：**`parsed_by` 等于当前用户本人**时，允许覆盖该行。

## 规则

- 覆盖者必须是该行的 `parsed_by`。判定用 SQL 的 `IS` 而不是 `=`：`parsed_by` 可为 NULL
  （未登录的历史数据），`=` 在 NULL 上永不成立，而 `IS` 是 SQLite 里唯一能正确表达
  「相等或两边都是 NULL」的比较符。
- 覆盖**不经过占位**。占位（`status='pending'`）的意义是「这一行此刻没有可信内容」；
  重新解析期间旧内容仍然有效，把它改回 pending 会让所有复用者在几秒钟内看到空白。
  因此覆盖走独立语句 `WHERE status='ready' AND parsed_by IS ?`。
- 覆盖失败（模型报错、断流）**不删除、不回滚**。旧内容继续对所有人可见，用户的钱按原样退回。
  这是「不动旧内容」的直接推论。
- 覆盖**照常扣额度**。它调了模型，代价与首次解析相同；BYOK 模式下不扣（用户自付费）。
- 覆盖**改写所有权**：覆盖后 `parsed_by` 仍是原主（本来就是他），不转移。

## Consequences

- `videos.parsed_by` 从「只是个统计字段」升级为**写权限的判定依据**。这是它建表时就有、
  此前无人读的那一列，现在有了第一个读者。
- 复用横幅上的「重新解析」不再是死按钮：owner 点击会真的重跑并覆盖。
  后来者看到的是明确的拒绝文案，而不是一个点了没反应的按钮。
- 社区里可能出现「同一条视频，作者改过两次」的历史。后者覆盖前者是预期行为。

## Considered Options

- 保留多版本并让作者选：详情页要加版本切换器，成本远大于收益，且违反
  「同一链接只呈现一份总结」的核心模型。
- 任何人都能覆盖：即 0006 否决的方案，理由不因本次修订而改变。
- 覆盖时把行改回 pending：复用者会在重新解析的几十秒里看到空白，
  且失败后要处理「空行」与「旧内容」两种遗留状态。此路不通。
