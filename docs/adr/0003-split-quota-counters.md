# 解析额度与对话额度分离

项目不做会员制，所有账号统一享有每日免费额度。
解析（产出总结、思维导图、标签）与追问（针对已有内容提问）是两种成本性质不同的动作：前者含字幕提取与一次批量生成，后者只是一次模型调用。
因此拆成两个独立计数器，各自在每日重置。

## Consequences

此前总结与问答共用一个计数器（且有一条测试锁定「问答不能变成绕过总结限额的免费通道」），
拆分后该测试契约需要修订——这是有意的改变，不是回归。
所有额度数值从环境变量读取，不硬编码。

另需注意：现有实现中总结与思维导图是两次独立的模型调用，但只扣一次额度。
新增标签产出后，三者应合并为一次「解析」动作、共用同一个解析额度。

## Considered Options

- 保持共用一个额度：实现最省，但用户无法区分「今天还能生成几个总结」与「还能追问几个问题」，
  且社区上线后追问会挤占生成额度，两者互相影响。
