# 视觉识别改为石墨 + 湖蓝，废止把 blue 色阶重映射成紫罗兰的做法

全站主色由「深空蓝底 + 紫罗兰主色 + 品红强调」改为「石墨底 + 天蓝主色 + 橙色强调」。

| 角色 | 暗色 | 明亮 | 用途 |
|---|---|---|---|
| 底 | `#0e141b` | `#f8f9f9` | 页面底 / 网格线载体 |
| 面板 | `#181f25` | `#ffffff` | 卡片、弹窗 |
| 主色 | `#2fa1da` | `#1f7ead` | 按钮、链接、激活态 |
| 强调 | `#f49a34` | `#b66b16` | 全站唯一暖色，承担「视频」语义 |
| 信息 | `#60ebc6` | `#1da581` | 链接、提示、思维导图 |

实测对比度（WCAG，正文需 ≥4.5）：正文/背景 **9.35**、主色/背景 **6.37**、强调色/背景 **8.39**。
色相全部避开 240°–300°；强调色与主色色相差 168°，一眼可分。

橙色是全站唯一的暖色结构色，与市面紫调 AI 产品形成区分，也承接「视频」这个主题。

## 这次改的不是审美，是一处结构性缺陷

改动前实测（2026-10-03，ripgrep 计数）：679 处令牌引用里 **553 处**挤在色相 220°–280° 这条窄带。
根因有两条，都写在 `frontend/src/style.css` 的 `@theme` 里：

1. `:35-45` 把 Tailwind 整条 `blue` 色阶**重映射成了紫罗兰**（注释自己写着「blue → violet 紫罗兰主色」，
   `--color-blue-500: #7c3aed`）。于是全站 92 处 `bg-blue-*` 没有一处是蓝色，实际全是紫。
2. `:11-33` 把 `gray` 与 `slate` 两条色阶**重映射成同一组深海军蓝**，`gray-50` 与 `slate-50`
   字面重复都是 `#161f36`。206 处「中性色」因此都带蓝偏，不是灰。

结果是：真正的蓝 0 处、真正的绿 0 处作为结构色，`emerald/amber/yellow` 的 33 处全是状态提示小方块。
「蓝紫色滥用」不是配色审美问题，是重映射造成的**可观测事实**。

## 品牌标记豁免：Logo 保持紫 / 粉 / 青，不跟随主题

**这是全站唯一的例外，且是刻意的。**

`PixelLogo.vue` 的 6 个方块（`#7C3AED` `#A855F7` `#EC4899` `#A855F7` `#06B6D4` `#06B6D4`）
与底板（`#161F36`）保持改动前的品牌原色，**不引用任何主题变量**。

理由有两条，第二条是决定性的：

1. 品牌识别依赖的是这一坨紫粉青方块在用户心里的**固定形象**。
2. Logo 出现在浏览器标签、书签、Windows 磁贴、PWA 图标上的那些地方，
   **不读 CSS 变量，也不跟随 `data-theme`**。如果方块跟着主题变，
   明亮主题下页内是蓝橙方块、标签页上还是紫粉青 —— 同一枚 logo 两处对不上。
   换句话说：**主题化 logo 只会让它在不同上下文里互相矛盾。**

用户在看到改后的蓝橙方块后明确要求「图标改回这个配色，其他内容按新的来」。
所以范围是：只有图标回到品牌色，UI 其余部分（导航激活态、功能卡、徽章、
页脚、思维导图、空态母题）一律走石墨 + 湖蓝。

⚠ **这个文件已经被「顺手改成新配色」动过一次。** 当时没有任何断言检查 Logo 的
具体颜色，全部用例保持绿色，改动静默通过。因此 `theme.test.mjs` 现在有一组
断言盯着它：不得出现 `var(--color-*)`、6 个方块必须是品牌色序列、底板与描边固定、
favicon 与组件底板一致、Windows 磁贴跟随。7 条变异实测全部转红。

顺带修掉一处原有不一致：favicon 的底板原本是 `#0F1729`，组件里是 `#161F36` ——
同一枚 logo 在页内和标签页上是两种深蓝。现统一为 `#161F36`（色偏更足，
在石墨页面底上不会糊掉）。

## Consequences

**`blue-*` 归位后，92 处主色用法一行都没改。** 这不是巧合：`bg-blue-*` 一直是主色位，
只是被重映射到了紫罗兰。新色板的主色恰好是蓝，于是**名字终于和它渲染的东西一致了**，
这次事故的根因随之消失。需要改名的只有落在 240°–300° 区间的那几族，共 66 处：
`violet`/`indigo`/`purple` → `blue`，`coral`/`pink` → `amber`，`teal` → `cyan`。

**新测试 `frontend/tests/theme.test.mjs` 守住这条线**：断言 `@theme` 里没有任何色值
落在 240°–300°，且 `blue-*` 必须落在蓝区 185°–240°。删掉这些色值是一次性动作，
没有测试守着的话，下一个人加一条 `text-purple-500` 就把它悄悄加回来了，而既有用例仍然全绿。

**城墙顶线换色时 `nav-wall.test.mjs` 会先红**：它把 `HeroSection.vue` 里 6 条顶线的硬编码 hex
与 `@theme` 对账。原断言写死了 `violet/purple/pink/cyan` 四个色族的代表色，已改为
**从 `@theme` 反查 hex 属于哪个色族、断言横跨 ≥3 族** —— 守住原意（是色谱而非同族深浅），
且不再需要每次换配色都改测试。已用变异确认该护栏仍能转红。

## Considered Options

- 保留深空蓝底，只把主色换成钢青：改动最小，但中性色的蓝偏仍在，区分度问题没解决。
- 石墨 + 翡翠青（H 164°）：另一支候选，对比度同样充足。最终选湖蓝是用户在带 WCAG
  实测的配色探索器里拍板的方向，两者都满足「避开蓝紫 + 内敛 + 有区分度」。
- 暖石墨 + 琥珀铜为主：视频/影院气质最强，但削弱了「AI/科技」的读法。
- 磷光终端（墨绿黑 + 荧光绿）：区分度最高，但荧光绿在明亮主题下难以延续，两套主题气质会撕裂。
